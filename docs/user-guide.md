# User guide

Reference for using squalify: the CLI, the library, the formats, the values policy, the guarantees and troubleshooting. New here? Start with [Getting started](getting-started.md); for recipes see [Examples](examples.md); for every descriptor member see [descriptor.md](descriptor.md).

## CLI

```text
squalify profile <path> [options]

  -o, --output <output>                      Write the descriptor to this file instead of stdout
  --include-values                           Include literal data values in the descriptor
  --include-values-for <include-values-for>  Include literal values only for the named preamble key, annotation label,
                                             key=value key or column (repeatable; matched whole, ASCII case-folded)
  --max-bytes <max-bytes>                    Read at most this many bytes, cut at a whole line; adds a scope section, and
                                             no file.sha256 unless the whole file was read (see Reading only a prefix)
  --max-first-record-bytes <n>               With --max-bytes: fail, profiling nothing, when the first record (line
                                             terminator included) is longer than n bytes (see Reading only a prefix)
  --verbose                                  Print full exception details
  -?, -h, --help                             Show help and usage information

squalify --version
```

- **One file per run.** `<path>` is a file. A directory is an error (see [Examples](examples.md#profile-a-directory) for a loop).
- **Output.** The descriptor is UTF-8 JSON with LF line endings and no BOM. Without `-o` it goes to stdout and nothing else is printed there. With `-o` the file is written to `<file>.tmp` and then moved over the target, so a reader sees the old file or the new one, never half of one; stdout stays empty. A failed run leaves stdout and an existing output file untouched.
- **Exit codes.** 0 on success; 1 on any error: a missing file, a directory, an unreadable file, an unwritable output, or a usage error (an unknown command, a missing argument). The message goes to stderr: for a file or output error it is one line, which includes the underlying reason; a usage error prints the message followed by the help text. `--verbose` adds the underlying exception's type and stack trace when there is one (an unwritable output, for example); for a missing file or a directory it adds nothing. Problems in the file's content are not errors: they are listed in `issues` and the exit code is 0.
- **`--version`** prints the package version. It is the same string as `tool.version` in every descriptor.

## Library

Add `squalor.squalify` (.NET 10). It holds the same profiler the CLI uses.

```csharp
using squalor.squalify;

var options = ProfileOptions.Create(includeValues: false, includeValuesFor: ["Lot"]);
Descriptor descriptor = Profiler.Profile("data.csv", options);
byte[] json = DescriptorWriter.ToBytes(descriptor);   // the exact bytes the CLI writes
```

| Member | Use |
|---|---|
| `Profiler.Profile(string path, ProfileOptions options)` | Profile a file. |
| `Profiler.Profile(IProfileSource source, ProfileOptions options)` | Profile other bytes. An `IProfileSource` has a bare `Name` (not empty, no `/` or `\`; it is the only name that reaches the descriptor), a `Length`, and `Open()`, which returns a fresh stream for each pass. A backslash is refused on every platform, also on macOS and Linux where a file name may hold one: the error says so, and the file must be renamed to be profiled. |
| `Profiler.ProfilePrefix(IProfileSource source, ProfileOptions options)` | Profile the start of a source and get back the exact bytes the descriptor describes, from one read: a `ProfiledPrefix` with `Descriptor`, `Prefix` (a `ReadOnlyMemory<byte>`) and `Scope` (a `ScopeSection`). `options.MaxBytes` is required. See [Reading only a prefix](#reading-only-a-prefix). |
| `ProfiledPrefix` | The result of `ProfilePrefix`: a sealed class with the get-only `Descriptor`, `Prefix` and `Scope`, and no public constructor, so only `ProfilePrefix` creates one and the descriptor describes `Prefix` by construction. `Scope` is the same instance as `Descriptor.Scope`. Equality is by reference and `ToString()` prints the sizes, not the bytes. |
| `ProfileOptions.Create(includeValues, includeValuesFor, maxBytes, maxFirstRecordBytes)` | The options; the allow-list is stored as a sorted set. `maxBytes` is optional (null reads the whole source) and `maxFirstRecordBytes` is optional (null: no ceiling; it needs `maxBytes`); see [Reading only a prefix](#reading-only-a-prefix). |
| `DescriptorWriter.ToBytes(descriptor)`, `DescriptorWriter.Write(descriptor, stream)` | Write the canonical JSON bytes. |
| `Descriptor` | The model: `Tool`, `Options`, `Limits`, `File`, `Encoding`, `Format`, `Kind`, `Layout`, `Fingerprint`, `Hints`, `Issues`, `Evidence`, and `Table`, `Sections`, `Binary`, `Stdf` or `Scope` when they apply. Plain records, mirroring [descriptor.md](descriptor.md). They compare by value: two descriptors are equal (`==`, `Equals`, same `GetHashCode` within one process) when every member is equal, the members of every list compared in order and text compared ordinally. `Limits` holds the caps in effect; the defaults are not API, so read them from `Descriptor.Limits` (the `limits` section). `ProfiledPrefix` is the exception: a class, compared by reference. |
| `SqualifyException` | Every public failure: a missing file, a directory, an empty path, an unreadable source, an invalid source name, an invalid option, a duplicate key given to `CountMap.FromOrdinal` or `FromNumeric`, a first record longer than `maxFirstRecordBytes`. Lower-level IO exceptions are wrapped. |

A complete program is in [Examples](examples.md#use-the-library-to-pick-an-import-route). The library reads the file; it does no network access and holds no state between calls.

## Formats

| Family | Today | What is described |
|---|---|---|
| Delimited text | Fully profiled | CSV, TSV, `;`, `\|` or whitespace separated. Delimiter, quoting, padding and decimal separator; preamble, annotation rows (such as limits), header, units row, data and footer regions; repeated header-and-table blocks (one `block` region each, see [descriptor.md](descriptor.md#several-blocks)); row classes; per-field profiles (type, nulls, null tokens and exact null spellings, statistics, shapes, units from header names); the exact spelling of all-null rows. |
| Plain text | Generic profile | Encoding, line endings, line kinds, longest line. |
| Binary | Generic profile | Named magic (gzip, zip, pdf, sqlite, hdf5, `parquet` and others), byte histogram, entropy. Nothing is decompressed or unpacked. |
| Empty | Generic profile | A zero-length file has family `empty`. |
| Touchstone (`.sNp`, `.ts`) | Planned | Profiled as text for now. |
| Key=value / INI | Planned | Profiled as text for now. |
| STDF V4 | Planned | Profiled as binary, with the `stdf-le` or `stdf-be` magic hint, for now. |

Parquet is not in v1: a Parquet file gets the binary profile and the `parquet` magic hint. Also planned: the `kind` label beyond `text`, `binary` and `empty`. Malformed content is described, not rejected: problems become `issues` and the descriptor is still written. The issue codes are listed in [descriptor.md](descriptor.md#issues).

## Values policy

By default a descriptor holds names, structure and statistics, but no literal data values.

| Always included | Only with `--include-values` |
|---|---|
| Header names, preamble keys, annotation labels | Preamble values, annotation-row cells, comment text |
| Counts, nulls, null spellings (also of all-null rows), types, shapes, lengths | Top values and text min/max of a column |
| Numeric and temporal min, max, mean, quantiles (not for a constant column) | Units-row text, statistics of a constant column |
| Units parsed from header names | Value-bearing `hints.stableLines` regexes (comment and text lines) |

`--include-values-for <name>` opens only the named preamble key, annotation label or column, compared whole with ASCII case folding. A name that matches several members opens all of them; a name that matches nothing is reported as the issue `includeValuesForUnmatched`. The complete list is in [descriptor.md](descriptor.md#values-tier), and the reasoning in [design.md](design.md#values-tier). A value that may not be written is never held in memory.

Header names (trimmed as `name`, and exactly as written as `rawName`) and preamble keys are always included, and can themselves identify a file. Review a descriptor before sharing it.

## Guarantees and stability

- **Deterministic.** The same input bytes, options and squalify version give the same descriptor, byte for byte, on any OS, CPU or culture, within one .NET runtime major version. The JSON writer takes its escaping of unassigned characters from the runtime's Unicode tables, so moving to another runtime major can change those bytes; squalify does not guard against that, so pin the package version and the runtime ([descriptor.md](descriptor.md#canonical-form)). Fingerprint hashes are identical across runtimes. Output never depends on time, path, machine or thread timing, and there is no machine learning, no LLM and no network access.
- **Describe, don't decide.** squalify does not match files against known types, propose configs or convert anything. Consumers do that from the descriptor.
- **Explainable.** Every inference has an `evidence` entry with its candidates and scores.
- **Versions.** The package version, `squalify --version` and `tool.version` are one string. The schema is a draft until the v1 schema freeze: before 1.0 a minor version may change the descriptor. After the freeze, adding optional keys bumps the schema's minor version and removing or renaming one bumps the major. Consumers must ignore unknown keys. See [the versioning policy](descriptor.md#versioning-policy).
- **Fingerprints.** `fingerprint.version` changes whenever a projection changes. Compare hashes only when it matches.
- **API added in 0.3.0 (library).** (sq-38) The public record `SketchLimits` (`HllPrecision`, `RankError`, `BudgetBytes`), the type of the new `Limits.Sketches`. (sq-42, sq-43) The public record `NullSpellingLimits` (`Max`, `MaxChars` and, from sq-43, `MaxDistinctOther`: the bounds on the null spellings and on the distinct count of the dropped ones, 64, 256 and 64 today; all three are required, as the record ships first in 0.3.0), the type of the new `Limits.NullSpellings`; its `Default` is internal, like `Limits.Default` and `SketchLimits.Default`: every default cap is internal, and a consumer reads the ones in effect from the `limits` section of a descriptor. (sq-40) `Profiler.ProfilePrefix` and the sealed class `ProfiledPrefix` (the descriptor and the exact prefix bytes it describes, from one read); `ProfilePrefix` changes no existing signature, `IProfileSource` is unchanged, and `ProfilePrefix` itself adds no descriptor member: it returns the same descriptor as `Profiler.Profile` for the same source and options when the source's `Length` is its true size. (The one behavior change of sq-40 is listed under the breaking changes below.) (sq-41) `CountMap` gained `==`, `!=` and `IEquatable<CountMap>` (value equality; `CountMap.Empty` and the key/value enumeration are unchanged).
- **Breaking changes in 0.3.0 (library).** (sq-39) `ProfileOptions` and `ProfileOptions.Create` gained a trailing `maxFirstRecordBytes` parameter (optional, so source-compatible; the signatures changed, so a compiled consumer must be recompiled); the option is not written to the descriptor. (sq-40) `Profiler.Profile` with `MaxBytes` now throws `SqualifyException` for a source that reports a negative `Length` (the result was undefined before; a valid source is unaffected); `Profiler.ProfilePrefix` and `ProfiledPrefix` are new (above). (sq-38) `Limits` gained a trailing positional optional member `Sketches` (`SketchLimits?`; null, the default of the parameter, reads as the full precision, and the profiler always sets it). It is optional, so source-compatible for code that constructs a `Limits`, but binary-breaking for a compiled consumer that constructs or deconstructs one: recompile, and note that a 14-element deconstruction of `Limits` stops compiling (it has 15 elements). (sq-38) `limits.sketches` is added to every descriptor (14, 0.001, 67108864 unless a table of more than 547 fields scaled it), and the effective `relativeStdError` and `rankError` of a field can now differ from 0.008125 and 0.001; nothing else in a descriptor changes. (`FieldCaps` also gained two defaulted members, but it is internal.) (sq-42) `Limits` gained a second trailing positional optional member `NullSpellings` (`NullSpellingLimits?`; null, the default of the parameter, reads as the bounds the profiler enforces, and the profiler always sets it), with the same compatibility as `Sketches`: source-compatible for code that constructs a `Limits`, binary-breaking for a compiled consumer that constructs or deconstructs one (recompile; a 15-element deconstruction stops compiling, the record has 16 elements). `limits.nullSpellings` (`max` 64, `maxChars` 256) is added to every descriptor and nothing else in a descriptor changes. (sq-43) `FieldProfile` gained two trailing optional members, `NullSpellingsOtherDistinct` (`long`) and `NullSpellingsOtherDistinctCapped` (`bool`), and `RowClassesInfo` gained `AllNullRowSpellingsOtherDistinct` (`long`) and `AllNullRowSpellingsOtherDistinctCapped` (`bool`), as sq-36 did for the spelling members: source-compatible for code that constructs one (the new members default to 0 and false), binary-breaking for a compiled consumer that constructs or deconstructs one (recompile; a deconstruction of either record stops compiling, each has two more elements). The members count the distinct spellings among the `Other` counts, exactly up to the cap in `limits.nullSpellings.maxDistinctOther` (64) and marked `Capped` beyond it. Descriptors: `limits.nullSpellings.maxDistinctOther` (64) is added to every descriptor, `table.rowClasses.allNullRowSpellingsOtherDistinct` is added to every delimited table (0 when no spelling was dropped), and a field that dropped a spelling past the bounds gains `nullSpellingsOtherDistinct` (and, past the cap, `nullSpellingsOtherDistinctCapped`), while the table always writes `allNullRowSpellingsOtherDistinct` and gains `allNullRowSpellingsOtherDistinctCapped` only past the cap; nothing else in a descriptor changes. (sq-41) `Limits.Default` is now internal: a consumer that read the nominal caps from it reads them from the `limits` section of a descriptor (`Descriptor.Limits`) instead; no descriptor byte changes. `SketchLimits.Default` and `NullSpellingLimits.Default` are internal as well (`SketchLimits.Default` was public only in the work between 0.2.0 and 0.3.0, so no release shipped it). The model records now compare by value: `Descriptor` and the records that hold a list (`Issue`, `Evidence`, `Hints`, `LayoutSection`, `Region`, `AnnotationRow`, `FieldProfile`, `TableSection` and the others), `ProfileOptions` and `CountMap` (its new operators are listed above) compare their members in order where they used to compare lists and maps by reference, so code that relied on two descriptors made from the same bytes being unequal, or that put one in a `HashSet` or `Dictionary` as a reference key, now sees them equal (hash codes are good for one process only). `CountMap.FromOrdinal` and `FromNumeric` throw `SqualifyException`, not `ArgumentException`, on a duplicate key (a null argument still throws `ArgumentNullException`), and `new FileSource("")` and `Profiler.Profile("", options)` throw `SqualifyException` (the CLI prints "Cannot profile an empty path: give the path of a data file." without a parameter name) where they threw `ArgumentException`; a null path still throws `ArgumentNullException`. A source name with a backslash is still refused, now with a message that names the backslash.
- **Breaking changes in 0.2.0 (library).** `ProfileOptions` and `ProfileOptions.Create` gained a `maxBytes` parameter (optional, so source-compatible; the signatures changed, so a compiled consumer must be recompiled). `FileSection.Sha256` is now nullable: it is absent when only a prefix was read. A descriptor made without a byte limit is unchanged. `FieldProfile` gained the trailing optional members `NullSpellings` (the null values by exact spelling, over all data records; never null from the profiler, empty when there is none) and `NullSpellingsOther`; `RowClassesInfo` gained `AllNullRowSpellings`, `AllNullRowSpellingsMixed` and `AllNullRowSpellingsOther` (the all-null records by their one shared spelling); a compiled consumer that constructs a `FieldProfile` must be recompiled, and `NullTokens` is unchanged.

## Limits and large files

The whole file is streamed in bounded memory and nothing is sampled (unless you set `--max-bytes`, which reads only a prefix; see [Reading only a prefix](#reading-only-a-prefix)): counts, min, max, mean, standard deviation and nulls are exact for any size. The expensive per-column statistics are exact up to fixed caps, recorded in the descriptor's `limits`:

| Statistic | Exact up to |
|---|---|
| Distinct values per column | 10,000 |
| Quantiles per column | 100,000 values |
| Shape masks per column | 64 masks, and 53,312 characters of mask text |
| Regions | 1,000 |
| Header-detection sample | 1,000 records |
| Row classes | 64 |
| Null spellings per column, and all-null row spellings per table | 64 spellings of at most 256 characters each (`limits.nullSpellings.max` and `maxChars`; the rest are counted in `nullSpellingsOther` and `allNullRowSpellingsOther`, and how many different ones in `nullSpellingsOtherDistinct` and `allNullRowSpellingsOtherDistinct`, exactly up to `maxDistinctOther` = 64 and marked `Capped` beyond) |

A global budget shrinks the first two caps, and the mask text, for very wide tables (100 columns or fewer keep the full caps); `limits.distinctPerField`, `limits.quantilePerField` and `limits.shapeCharsPerField` show the effective values. Past a cap a deterministic sketch takes over and the descriptor says so: `distinct` is a HyperLogLog estimate with `approximate: true` and `relativeStdError` (0.008125, one standard error, for a table of up to 547 columns), and `numeric` and `temporal` quantiles come from a Greenwald-Khanna summary with `approximate: true` and `rankError` (a sibling of `quantiles` and `approximate`, 0.001 for a table of up to 547 columns, the worst-case rank error as a fraction of the values). Both members are absent while the value is exact. `min`, `max`, `mean` and `stddev` do not depend on the caps. The sketches have a size per column, so a table of more than 547 columns gets coarser sketches (larger `relativeStdError` and `rankError`; `limits.sketches` always says which precision is in effect, and each column repeats it) to keep all of them nominally within a budget of their own (64 MiB, apart from the read-buffer headroom; columns of few distinct values can hold more than their nominal share, and that is counted in the memory estimate): 2,000 columns give 0.01625 and 0.004. See [design.md](design.md#bounded-memory-and-sketches).

## Reading only a prefix

`--max-bytes <n>` (library: `ProfileOptions.MaxBytes`) profiles the start of a file instead of all of it, for a quick look at a large file or a classification that a longer read will confirm. squalify reads at most `n` bytes and cuts at the last whole line, so the profile ends on a whole record; a file whose first `n` bytes are binary is cut at `n` exactly. There are two exceptions to "at most `n`": a CRLF that straddles the limit adds one code unit, and **a first line longer than `n` is read to its end, however long, with no ceiling** unless you set `--max-first-record-bytes` (below); a file with no line terminator is read whole. The profile is therefore never empty for a file that has data, and `scope.bytesRead` then exceeds `n`. The descriptor says what it read in a top-level `scope`, and `file.size` stays the length of the whole file:

```bash
squalify profile sweep-preamble.csv --max-bytes 310 | jq -c '{file, scope, rows: .table.rows, regions: [.layout.regions[] | [.kind, .lines[0], .lines[1]]]}'
```

```json
{"file":{"name":"sweep-preamble.csv","size":448},"scope":{"maxBytes":310,"bytesRead":300,"complete":false},"rows":11,"regions":[["preamble",1,7],["header",8,8],["units",9,9],["data",10,20]]}
```

- **Everything describes the prefix.** Every section, including the text-or-binary decision and the charset, is computed from the first `scope.bytesRead` bytes alone, as for a file that holds just those bytes. A `footer` that the file has past the cut is not seen. The record caps in `limits` limit how a record is profiled, not how much of it is read.
- **`file.sha256` is absent unless the whole file was read.** It is absent while `scope.complete` is false, because the hash of the whole file needs a read of all of it. With a limit at or above the file size, `scope.complete` is true, `sha256` is written and the rest of the descriptor equals the unlimited one.
- **A ceiling on the first line is opt-in.** `--max-first-record-bytes <n>` (library: `ProfileOptions.MaxFirstRecordBytes`) refuses a file whose first record, line terminator included, is longer than `n` bytes, instead of reading that record to its end. squalify then stops reading at `n` bytes (one more code unit when a CR ends there, to see whether an LF follows), prints a message that names the option and `n`, profiles nothing and exits 1 (the library throws `SqualifyException`). Use it when you know your files have short first lines, to turn away a huge file with no line breaks without reading it. It is off by default, so nothing above changes, and it is rejected without `--max-bytes` (zero or less is rejected too). `n` counts bytes of the code units of the charset: a CRLF is 2 bytes, a UTF-16 unit 2, a UTF-32 unit 4; a BOM counts, as part of the first bytes of the file. A record of exactly `n` bytes is accepted; a CR that is byte `n` is accepted unless an LF follows it. A binary file (one whose first `--max-bytes` bytes are binary) has no records and is not subject, and no record after the first is checked. A file that passes gives the same descriptor as without the option, which is not recorded in it. The check decides the charset from the first `n` bytes (or the limit, if that is smaller) when they are text, so a head with no BOM and no UTF-16 or UTF-32 NUL pattern is counted one byte per unit. When those `n` bytes look binary (for example a few control bytes, or the `00 00` start of a UTF-32BE byte order mark), squalify sniffs the whole `--max-bytes` window instead, and a text window is checked with its charset; reading stays within `--max-bytes`.
- **The cut rule is a contract.** The prefix that `--max-bytes` (library: `MaxBytes`) selects is cut by this rule, which a consumer may rely on, and any later change to it is a documented breaking change. Text or binary, and the charset, are decided by sniffing the bytes inside the limit, not the whole file. A file whose bytes inside the limit sniff as binary is cut at the limit. Otherwise it is cut after the last LF, CR or CRLF whose code unit lies inside the limit, counting code units of the charset sniffed from the bytes inside the limit (a UTF-16 unit is 2 bytes, a UTF-32 unit 4; a limit inside a unit counts whole units only). A CR that ends the limit takes the LF after it, so a CRLF is never split. With no terminator inside the limit, the read goes on to the first terminator (a CR takes the LF after it) or the end of the file, whichever comes first. A file whose length is at or below the limit is taken whole. `scope.bytesRead` is the length of the cut, and `scope.complete` is true exactly when the cut reaches the end of the file. A limit shorter than a byte order mark (or than the few bytes the sniff needs) can sniff differently from the whole file, because the sniff sees only those bytes: a binary file with a tiny limit can be cut at a line terminator, a UTF-16 or UTF-32 file can be read as one byte per unit, and a UTF-32BE file can be called binary. A change to the sniff that moves a cut is a documented breaking change.
- **Getting the bytes you profiled: `Profiler.ProfilePrefix`.** `Profiler.ProfilePrefix(source, options)` returns a `ProfiledPrefix` (sealed, get-only `Descriptor`, `Prefix` and `Scope`, created only by this method): the descriptor and the first `Scope.BytesRead` bytes of the source, cut by the rule above, so a program that parses the same bytes itself (for example to read the first rows) sees exactly what squalify described, with no cut rule of its own to keep in step. The source is opened once and read once: the bytes go into one buffer that every pass shares, and the descriptor is computed from that buffer, so it equals the one `Profiler.Profile` gives for the same source and options, for a source whose `Length` is its true size (`Profile` reads past a `Length` that is shorter than the data when the limit is at least that length, because it hands the raw stream to the byte pass; `ProfilePrefix` never does). `file.size` is `IProfileSource.Length`, the whole source, and `file.sha256` is present only when `scope.complete` is true. The source is never read past its declared `Length`: bytes beyond it are not part of the file as the source declares it (a source that declares 10 bytes and holds more gives a buffer of at most 10 bytes, `file.size` 10, and a `Prefix` and `scope.bytesRead` of the bytes read); a `Length` larger than the data gives only the data there is. `Prefix` is a copy-free view of the buffer that the profiler no longer uses: it does not change the descriptor, and a later call has its own buffer. Its backing array may be a little larger than the prefix (see the next point). `MaxBytes` is required (a null limit throws `SqualifyException`, because it would buffer the whole source), and so is a source that reports its length (a negative `Length` is rejected). The same exceptions as `Profile` apply, including the first-record ceiling.
- **The buffer is bounded by the limit plus the overshoot.** `ProfilePrefix` holds at most `MaxBytes` bytes plus the overshoot past it: one code unit when a CR ends the limit, or the rest of the first record when it is longer than the limit (read to a few KiB past its end). The backing array is the limit plus at most 4 KiB for a small overshoot (for example the LF after a CR that ends the limit), and about the limit plus twice the overshoot (and a few KiB) for a long first record; it is never larger than the source's declared length. Set `MaxFirstRecordBytes` to cap the overshoot: a longer first record is then refused after reading at most that many bytes plus one code unit, with no more buffered. Without it, a text file with no line break is buffered whole, so give `ProfilePrefix` a ceiling when the files are not trusted. A limit larger than one array can hold (about 2 GiB) is rejected with `SqualifyException`. `Profiler.Profile` with a limit does not buffer: it streams, reading the source several times.
- **No limit, no `scope`.** Without `--max-bytes` the descriptor has no `scope` member and is unchanged.
- **A zero or negative limit is an error.** The library needs `IProfileSource.Length` to be the whole size; a source that cannot report it should not be limited.
- **A quoted field with line breaks** that straddles the limit is cut at a line break inside it, so the last record of the prefix is a short one.

## Troubleshooting

**squalify says my text file is `binary`.** The byte pass calls a file binary when it has a known magic, a NUL byte (other than a UTF-16 or UTF-32 pattern), or more than 5% control bytes. Check `encoding.kind`, `encoding.controlBytes` and `hints.magic`, and the `evidence` entry for `encoding`. A UTF-16 file with a byte order mark is text; one without is text only when its NUL bytes follow the UTF-16 pattern. See [how it works, section 12](how-it-works.md#12-text-binary-or-empty).

**The delimiter or header is wrong.** Read `evidence`, stage `dialect` (topic `delimiter`) and stage `header`: each lists the candidates with scores and reasons. A header-less comma CSV whose first column is multi-word text and whose last column is an integer can be read as whitespace-delimited (a [known limitation](design.md#delimited-text)); a header row or a comma inside a cell usually settles it. A file with no viable delimiter gets the generic text profile, with the issue `tooIrregular` when a candidate was rejected as too irregular. Use `hints.dataStartLine` and `layout.regions` to see where squalify thinks the data begins.

**The encoding is `latin-1`, or I see `invalidUtf8`.** A file that is not valid UTF-8 is called `latin-1` (the evidence notes "possibly windows-1252" when bytes 0x80 to 0x9F occur). A few stray invalid bytes in otherwise valid UTF-8 or ASCII are tolerated (at most 8, and at most one per 64 KiB), reported as the issue `invalidUtf8` with byte offsets, and decoded as U+FFFD.

**I see `invalidUnicode`.** The file is UTF-16 or UTF-32 and holds a lone surrogate, a stray last byte or an impossible UTF-32 value. `encoding.invalidBytes` counts their bytes and the issue lists the byte offsets of the first 10. Unlike `invalidUtf8` there is no allowance: even one invalid unit is reported.

**The file is empty.** A zero-length file gets family `empty` and kind `empty`, with no error.

**I passed a directory.** Directories are not supported: the run fails with exit code 1. Loop over the files ([example](examples.md#profile-a-directory)).

**My STDF, Touchstone or Parquet file looks wrong.** They are not profiled in 0.1.x. STDF and Parquet get the binary profile with a magic hint (`stdf-le`, `stdf-be`, `parquet`), and Touchstone gets the text profile.

**A descriptor changed after an upgrade.** Expected before 1.0 while the schema is a draft. Pin the package version and the .NET runtime major version, and compare `tool.version` and `schemaVersion` in the descriptors.

**Where is the data?** Not in the descriptor, unless you opt in ([values policy](#values-policy)).

Found a bug or a file squalify mishandles? Report it in the [GitHub repository](https://github.com/squalor-xyz/squalify) and include the descriptor, not the file. See [Contributing](../CONTRIBUTING.md) to fix it yourself.
